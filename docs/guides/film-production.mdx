This guide describes the **hyperframes-film-studio fork**. Its first production feature prepares an edit from a local manifest. It copies hash-verified media into a new composition directory and retains shot IDs, candidate take IDs and camera/acting/dialogue notes.

## When to use it

Use preparation when selected footage already exists and you want to assemble picture and sound with repeatable frame timing. It runs locally and makes no provider calls. Existing film approvals remain authoritative.

The first version supports one continuous picture track, independent audio tracks, source trims and constant playback rates. The companion production inspector also supports explicit shot review and durable local job controls. Provider execution and automated ComfyUI jobs remain subsequent work.

## Prepare, check and render

From this fork's checkout, with its dependencies installed and packages built:

```sh
bun run film:prepare --manifest .film-workspace/inputs/manifest.json --output .film-workspace/exchange-v1
node packages/cli/bin/hyperframes.mjs lint .film-workspace/exchange-v1
node packages/cli/bin/hyperframes.mjs check .film-workspace/exchange-v1 --json
node packages/cli/bin/hyperframes.mjs render .film-workspace/exchange-v1 --output .film-workspace/exchange-v1.mp4
```

Preparation produces ordinary editable `index.html`, copied `assets/`, a portable `production.json` and a hash receipt. Run lint and browser check before previewing or rendering. Review the actual exported picture and sound before accepting a cut.

## Preserve edits and originals

Output must be a new directory. A second preparation into an existing directory fails, preserving timeline edits. Prepare another candidate in a different directory; automatic synchronization back to the manifest is not implemented.

The manifest accepts relative local paths and actual SHA-256 hashes. Missing/changed bytes, path escapes, invalid timing and unsupported fields fail explicitly. Picture audio is muted; place dialogue separately to make J/L cuts without doubling sound.

Private footage, manifests, renders and receipts belong under ignored `.film-workspace/`. Do not commit them. The complete manifest schema, examples and verification commands are maintained in the fork's `film-studio/README.md`.

## Inspect existing film records

The fork also provides a read-only intake command:

```sh
bun run film:import --workspace /path/to/Movies_Projects
```

It reports shot/reference/take counts, missing media, changed hashes and unresolved ID links without changing the source. Add `--output .film-workspace/import-v1` to save a candidate snapshot in a new directory. Imported approval declarations remain evidence; execution permission is always false. The result is not automatically a renderable composition. The complete intake contract is maintained in the fork's `film-studio/IMPORT.md`.

## Map shots and assign candidates

`bun run film:review --import <private-import.json>` creates an empty local review state. Explicit commands can link plan/legacy shots, assign references with their declared roles and hashes, and select compatible candidate takes. Project identity, import fingerprint, revision and history are checked. Changing a mapping invalidates its dependent candidate selection. Use a new output file for each saved review. This stage does not approve footage, create jobs or alter the timeline; see the fork's `film-studio/REVIEW.md` for the command contract.

## Use the production inspector

```sh
bun run film:inspect --import .film-workspace/import-v1/import.json --workspace /path/to/Movies_Projects --port 9362
```

Open the printed loopback URL to search shots, inspect direction notes and propose mappings, reference assignments and candidate takes. Every change requires a reason and uses the same revision-checked review service. Local previews require the optional workspace and unchanged imported media hashes.

Session changes stay in memory. Use **Download review** to save them, then add `--state <saved-review.json>` on a later startup to resume against the same import. **Reload session** refreshes the browser from the running server. Add `--jobs <existing-store>` to prepare selected-shot video intent and view saved job states. Add `--results-workspace <existing-directory>` to record local external receipts; it requires `--jobs`. The roots are fixed at startup, receipts must match the explicitly selected job and successful outputs remain hash-checked candidates. Jobs save automatically; review proposals still require Download review. Refused writes retain the typed form until you reload or switch shots. This companion screen does not submit provider jobs or change the timeline. See the fork's `film-studio/INSPECTOR.md` for startup, persistence and preview limits.

## Track prepared jobs and external results

```sh
bun run film:jobs --import .film-workspace/import-v1/import.json --store .film-workspace/jobs-v1 --operation init
bun run film:jobs --import .film-workspace/import-v1/import.json --store .film-workspace/jobs-v1
```

The checkout-local `film:jobs` command creates a private durable ledger; its default operation only shows saved state. `prepare` binds explicitly authored generation intent to a shot and saved review. `observe` records a matching external receipt, verifying any supplied local output hashes. Both require a current `--expected-revision` and a reason. Duplicate intent, conflicting external IDs, stale writes and invalid result paths are refused.

Routes are handoff labels; this stage does not call providers, compile vendor payloads, load models or grant execution/creative approval. Unknown outcomes stay on the same job for explicit reconciliation. Output bytes remain candidate evidence and are not placed on the timeline. The complete request/receipt schemas, commands and recovery limits are in the fork's `film-studio/JOBS.md`.


## Prepare a Kling producer handoff

The checkout-local `bun run film:kling-handoff` command previews or exports one blocked candidate from a prepared Kling video job. Supply the current store revision/request fingerprint, saved review, explicit native settings, canonical workspace and film path. It preserves the recorded model/prompt and rechecks local reference hashes.

Exported `runner-spec.json` retains null authorization and a submission block. The existing Movies producer release runner remains responsible for exact-payload approval, live capability checks, quotes/upload scope and submission. No provider calls occur here. Linux descriptor verification and Python 3 standard-library canonical hashing are required. See the fork's `film-studio/KLING-HANDOFF.md` for the full command/settings contract and `film-studio/TASKS.md` for remaining integration work.


## Place reviewed takes into a new edit

`bun run film:place --import <import.json> --review <review.json> --describe` prints the exact binding fields and selected candidate IDs for an authored cut plan. Add `--plan <cut.json>` for a read-only compiled preview; add both `--workspace <canonical-root>` and `--output <new-directory>` to prepare the new composition.

Shot order, trims, rate, frame timing and separate audio placement are explicit. Current selected take hashes and actual stream coverage are checked. Original IDs, full source direction and plan/review provenance remain in `placement.json`; existing timeline edits are never replaced. This creates a candidate edit, not creative approval. See the fork's `film-studio/PLACEMENT.md` and tracked `TASKS.md`.
